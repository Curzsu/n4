# N4 Monitor 算法侧：低算力顶会论文调研

调研日期：2026-10-22。核验了正式会议论文、作者仓库和公开运行说明，尚未安装运行原代码；复现难度属于依据依赖与资源需求作出的判断。

**首选主线：CRITIC 的工具反馈纠错＋Reflexion 的失败经验记忆，Self-Refine 作对照。** 想增加较新的研究，可选 ICML 2025 的 AWM；想做纯 CPU 的时序算法，可选 KDD 的 SPOT。

## 1. 筛选口径

- 只把正式主会论文列入主选，不把预印本、Workshop、Findings 当主会长文。NeurIPS、ICML、KDD 属于 CCF A；ICLR 在本表统一按国际顶会列示，分级以学校采用的目录版本为准。[CCF 官方目录说明](https://www.ccf.org.cn/Academic_Evaluation/By_category/)、[人工智能目录](https://www.ccf.org.cn/Academic_Evaluation/AI/)、[数据挖掘目录](https://www.ccf.org.cn/Academic_Evaluation/DM_CS/)
- **低算力指本地不进行大模型训练或部署**：LLM 走云 API，工具与小规模统计计算走 CPU；仍有 API 费用。少量统计参数拟合与训练大模型的资源需求不同。
- **迁移论文方法与复现原论文数字分开**：换现代模型、N4 数据和调用上限后，是方法迁移实验；不能直接声称复现了原论文分数。

## 2. 优先阅读与复现的论文

| 论文与出处 | 核心方法与 N4 用法 | 复现条件与建议 |
|---|---|---|
| **CRITIC: Large Language Models Can Self-Correct with Tool-Interactive Critiquing**；ICLR 2024 顶会。[论文](https://proceedings.iclr.cc/paper_files/paper/2024/hash/fef126561bbf9d4467dbb8d27334b8fe-Abstract-Conference.html)／[官方代码](https://github.com/microsoft/ProphetNet/tree/master/CRITIC) | 借助外部工具验证并修正输出。把工具换成 N4 规则校验与隔离回放，反馈阈值、死区、延迟和恢复行为错误 | **主推，方法复现难度低至中**。无需训练；原代码依赖旧 SDK、旧模型接口，需要适配。重点是具体反馈能否提高规则行为正确率 |
| **Self-Refine: Iterative Refinement with Self-Feedback**；NeurIPS 2023，CCF A。[论文](https://proceedings.neurips.cc/paper_files/paper/2023/hash/91edff07232fb1b55a505a9e9f6c0ff3-Abstract-Conference.html)／[官方代码](https://github.com/madaan/self-refine) | 同一模型生成、自己提意见、再改写。用于规则生成的“无外部反馈”对照 | **最容易起步**。无需训练；每轮批评与改写会增加 API 调用，部分脚本仍使用旧模型。适合作基线，不能用模型自评代替规则验收 |
| **Reflexion: Language Agents with Verbal Reinforcement Learning**；NeurIPS 2023，CCF A。[论文](https://papers.nips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html)／[当前作者代码](https://github.com/noahshinn/reflexion) | 把失败反馈总结成文本记忆，指导后续尝试。让 Agent 记住某类规则错误及修正策略 | **推荐，难度低至中**。不更新模型权重；多次尝试仍产生费用，原依赖较旧。先限定单任务内记忆，再研究跨任务复用 |
| **An LLM Compiler for Parallel Function Calling**；ICML 2024，CCF A。[论文](https://proceedings.mlr.press/v235/kim24y.html)／[官方代码](https://github.com/SqueezeAILab/LLMCompiler) | 模型生成有依赖的工具计划，调度器并行执行已就绪任务。用于并行查点位状态、规则和历史窗口 | **效率方向首选，难度中**。无需训练或 embedding；需实现依赖解析、并发限流和失败处理。保留模型规划与依赖调度，不能仅把 Java 查询改成并发就称为复现 |
| **Anomaly Detection in Streams with Extreme Value Theory（SPOT）**；KDD 2017，CCF A。[会议页](https://www.kdd.org/kdd2017/papers/view/anomaly-detection-in-streams-with-extreme-value-theory)／[第一作者维护实现](https://github.com/asiffer/libspot) | 基于极值理论拟合尾部，在线给出异常阈值。为 Agent 提供异常时刻、动态界限与超限信息 | **纯 CPU 首选，难度低至中**。需要正常段初始化和统计拟合。先在平稳序列或残差上评估；漂移场景不能直接假定 SPOT 适用。风险参数不是实际生产误报率保证 |

SPOT 定位为 Agent 调用的时序证据工具；其检测效果可以独立评价，无需把大模型放进每个采样点的计算链路。

## 3. 2025 年扩展候选：相关，但需要更多适配

| 论文与出处 | 可用于 N4 的算法方向 | 复现门槛 |
|---|---|---|
| **Agent Workflow Memory（AWM）**；ICML 2025，CCF A。[论文](https://proceedings.mlr.press/v267/wang25bx.html)／[官方代码](https://github.com/zorazrw/agent-workflow-memory) | 从成功轨迹归纳可复用流程，例如“定位点位→查规则→查历史→解释恢复条件”。比较人工固定流程与自动归纳流程 | 无需微调，但原代码面向 Mind2Web／WebArena，完整网站环境与长交互成本较高。**建议迁移工作流归纳机制，难度中**；不复建整套网页基准 |
| **Sufficient Context: A New Lens on Retrieval Augmented Generation Systems**；ICLR 2025 顶会。[论文](https://proceedings.iclr.cc/paper_files/paper/2025/hash/33dffa2e3d2ab74a783d1a8c292f66d9-Abstract-Conference.html)／[作者资源与提示词](https://github.com/hljoren/sufficientcontext) | 判断证据是否足以回答问题。扩展成“证据不足→补查缺失信息或拒答”，适合缺历史、缺规则版本的告警分析 | **领域贴合，但难度中**。作者仓库未核验到完整可运行训练脚本。低算力迁移可用 API 判别＋CPU 拟合小型逻辑回归；原完整方案使用 FLAMe 24B，部分路径还需多次采样，不能统称低成本 |
| **InstructRAG: Instructing Retrieval-Augmented Generation via Self-Synthesized Rationales**；ICLR 2025 顶会。[论文](https://proceedings.iclr.cc/paper_files/paper/2025/hash/cdce0de17dc3cf97019a35baa65aebd0-Abstract-Conference.html)／[官方代码](https://github.com/weizhepei/InstructRAG) | 从正确问答与材料合成证据解释，作为示例引导模型忽略干扰材料。适合“同名设备、过期规则、错误时间窗口”抗噪实验 | **只选 ICL 分支，难度中**。ICL 无需训练，但需正确问答与离线示例生成；原推理代码也需适配云 API。FT 分支使用多 GPU 全参数训练，不属于本轮低算力方案 |

Sufficient Context 的“足够”不等于材料真实、新鲜或规则版本正确。N4 的时间、来源与版本校验需要独立实现；自动选择补查工具也是拟新增的方法，并非原论文已有能力。

另外可看 **DAMP：Matrix Profile XXIV: Scaling Time Series Anomaly Detection to Trillions of Datapoints and Ultra-fast Arriving Data Streams**，KDD 2022，CCF A。[论文](https://dl.acm.org/doi/10.1145/3534678.3539271)／[原作者代码与教程](https://sites.google.com/view/discord-aware-matrix-profile/documentation)。无需深度训练，可检测静态阈值难发现的形状异常；官方实现为 MATLAB，Python 版本需要辨别第三方移植，因此列为备选。适合返回异常片段，不能把近似 profile 的剪枝平段逐点解释为真实异常强度。

## 4. 最适合形成算法工作量的三条路线

| 路线 | 可以提出并验证的改进 | 最小对比实验 |
|---|---|---|
| **A．工具反馈与经验记忆驱动的规则纠错，最推荐** | 面向 N4 规则语义组织错误反馈；按错误类型保留经验证的修正经验；限制迭代预算 | 一次生成、Self-Refine、CRITIC、CRITIC＋记忆；加入同预算无反馈多候选，评价隐藏回放通过率、错误接受率、调用成本 |
| **B．证据充分性驱动的告警分析，较新** | 联合证据充分性与时间／版本检查，选择回答、补查或拒答；可选加入 InstructRAG-ICL 抗噪示例 | 普通 RAG、仅模型置信度、充分性信号、加入领域检查；评价相同回答覆盖率下的正确率、错误回答率与补查次数 |
| **C．CPU 异常检测与证据解释，最省模型调用** | 先用 SPOT 检测，再按设备工况组织阈值与异常证据；需要形状异常时再评估 DAMP | 原静态阈值、MAD、SPOT；评价事件召回、误报次数、检测延迟和 CPU／内存，Agent 解释单独评分 |

执行时保留四条实验约束：

1. **独立真值**：规则回放需人工审核的目标事件序列；实际交互无目标预期时只展示轨迹供审核。检测使用独立异常标注或已知注入事件，预定义事件匹配与延迟起点，不能用原阈值告警作真值。无异常标签时只报告告警率、人工审核与开销；无根因标签时不评价物理根因准确率。
2. **公平预算**：固定模型、工具与输入，约束总调用和 tokens；Self-Refine 的批评、Reflexion 的反思及 AWM 的离线归纳都计入成本。LLMCompiler 另比较“同一计划串行／并行”以隔离调度收益。
3. **防止泄漏**：规则任务按场景族分组切分；跨任务记忆只从开发集构建。时序方法用正常历史拟合，随后按时间测试，不能用测试标签调阈值；报告未经 point adjustment 的指标。
4. **先小后大**：先用约 20 个案例测通流程与费用，再扩到 100—200 个独立审核任务；正式实验重复运行，保存版本、种子、工具结果与执行轨迹。

**建议先完成路线 A，用路线 B 或 C 作为后续扩展，首版不需要把全部论文组合起来。** 论文机制的适配、明确的方法改动与对照实验可以构成算法侧工作；仅接入框架或复刻提示词还不足以说明方法贡献。
