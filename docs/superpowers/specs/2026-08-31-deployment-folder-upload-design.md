# 部署数据文件夹上传设计

## 目标

在 `System → Device Deployment → Import Data` 中增加文件夹选择入口，使用户可以直接选择老师提供的 `KVTP-A0807` 目录，不再必须先压缩为 ZIP。

## 交互设计

- 保留现有 ZIP、拖拽及多选 CSV 上传能力。
- 在现有上传区域增加独立的 `Select Folder` 按钮。
- 选择文件夹后，浏览器递归返回该目录及其子目录中的文件。
- 前端仅保留扩展名为 `.csv` 的文件，扩展名匹配不区分大小写，其他文件静默忽略。
- 新选择的文件夹替换当前已选择的 ZIP 或 CSV，避免同一批数据被重复提交。
- 页面显示选中的 CSV 数量；没有 CSV 时给出提示，并保持 `Preview` 不可用。
- 选择完成后继续复用现有 `Preview → Confirm Import` 流程。

## 技术设计

- 使用隐藏的原生文件输入框，并设置 `multiple` 和 `webkitdirectory`，由浏览器完成目录递归枚举。
- 文件变化时，将筛选后的 `File[]` 写入现有 `deploymentImportFiles` 状态。
- 清空 Element Plus 上传列表和上次预览结果，确保界面状态与本次文件夹选择一致。
- 重置原生输入框的值，使用户可以连续选择同一个文件夹。
- 继续调用现有 `deploymentApi.importFiles()`；后端接口、解析逻辑和数据库写入逻辑不做修改。

## 兼容与异常处理

- 目标运行环境为 Chromium/Electron，支持 `webkitdirectory`。
- 不支持目录选择的浏览器仍可使用现有 ZIP 或多 CSV 上传。
- 文件夹中没有 CSV 时不发起预览请求，并显示明确提示。
- 目录层级和相对路径不参与业务关联；设备、模板和导航关联继续从 CSV 内容中解析。

## 验证

- 先增加失败测试，确认页面声明文件夹输入、递归选择属性、CSV 筛选和独立入口。
- 验证选择包含非 CSV 文件的目录时，只提交 CSV。
- 验证重新选择文件夹会替换旧文件并清除旧预览。
- 运行全部前端测试和正式构建。

## 非目标

- 不修改后端上传接口。
- 不修改数据库结构或数据。
- 不改变 ZIP 和多 CSV 的原有行为。
- 不根据目录名称推导设备或导航关系。
