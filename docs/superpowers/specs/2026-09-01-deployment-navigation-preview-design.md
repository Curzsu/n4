# Deployment Navigation Preview 设计说明

## 目标

让部署导入 Preview 明确展示导航树的新增业务组，并清理旧演示数据，使 `KVTP-A0807 - 副本` 可直接用于 D1 客户演示。

验收流程如下：

1. 导入文件夹并点击 Preview 时，若 `A1_MVP_D1` 不在当前有效导航树中，Preview 显示 `Navigation groups: 1 new`，并列出 `A1_MVP_D1`。
2. Preview 不写数据库。
3. 点击 Confirm Import 后，系统创建或恢复 `A1_MVP_D1 → MVP_D1`，并将 D1 设备挂载到 `MVP_D1`。
4. 用户删除 `A1_MVP_D1` 及其子节点后，再次 Preview 仍显示 `Navigation groups: 1 new`。
5. 设备、点位的 `new/reused` 统计保持原有业务键语义，不把导航组误计入设备数量。

## 方案

后端在现有 `ImportSummary` 中增加导航组新增数量和名称列表。导入解析阶段按 CSV 中不同的系统路径去重，只将系统路径的第一个业务组段计为一个导航组。当前有效树无法解析、但可以挂到已有一级根节点的路径计为 `new`；已逻辑删除的路径同样按“重新出现在当前树中”计为 `new`。

Preview 阶段只计算统计，不调用导航写入接口。Confirm Import 通过现有事务恢复匹配的逻辑删除节点或创建缺失节点，然后把复用的未挂载设备更新到叶节点。

前端在设备和点位统计之前增加导航组统计行，显示数量和业务组名称。已有导入文件选择、Preview、Confirm 和导航树刷新流程保持不变。

## 数据清理范围

只清理已确认的旧演示数据：

- 设备 `452`、`453`、`454` 及其关联点位。
- 已逻辑删除的 C1 导航节点 `27`、`28`。
- 导入文件夹中的旧 `A1_MVP_C1` 文件夹。

保留正式 A1 数据、D1 演示设备 `455`–`457`、D1 点位和共享告警规则。数据库清理前导出可恢复备份；文件夹中的旧 C1 文件移入可恢复位置，不影响导入文件夹最终内容。

## 验证

- 增加后端单元测试，覆盖缺失导航组 Preview 统计、逻辑删除导航组恢复和设备挂载。
- 增加前端静态测试，覆盖导航统计字段和显示文案。
- 运行部署导入回归测试、全部前端测试和生产构建。
- 在运行中的项目上执行删除 D1、Preview、Confirm Import 和导航树查询，确认 `A1_MVP_D1 → MVP_D1` 可见且有 3 台设备。
