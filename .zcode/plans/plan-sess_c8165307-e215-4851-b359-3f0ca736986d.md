# System Deployment 页实现计划

## 目标
在顶部导航栏新增 "System Deployment" 页（位于 Device Deployment 右边），用于对 dashboard 左侧导航栏（nav_node 两级树 + 设备挂载）做增删改查。

## 已确认的设计决策（grill-me 阶段已定）
1. **范围**：节点树 CRUD + 设备挂载/卸载（不编辑设备本身）
2. **布局**：左右双栏（左 el-tree 树，右 详情/设备面板）
3. **挂载层级**：设备只挂到二级节点；一级是纯分类容器（点一级聚合子节点设备）
4. **删除策略**：二次确认 + 级联删除（弹窗显示影响范围：将删除 N 个子节点、解绑 M 台设备）
5. **表单字段**：节点名 + 父节点选择 + 预设图标下拉 + 排序序号；node_level 自动推断
6. **设备挂载交互**：右面板已挂载列表 + "添加设备"弹窗（弹窗列出可挂载设备，勾选批量挂载）

## 约束
- 远程数据库（47.121.30.136）只读不改，所有操作在本地 n4_monitor 库
- 沿用现有 ApiResponse / @Transactional / 逻辑删除 / useGeneratedKeys 模式
- 不改 device_deployment 表结构（nav_node_id 已存在）
- 不动 LeftSidebar 在首页的渲染逻辑（System Deployment 页是独立管理视图）

## 任务 1：后端 - NavNodeMapper 加节点写操作

**文件**：
- `backend/src/main/java/com/n4monitor/mapper/NavNodeMapper.java`
- `backend/src/main/resources/mapper/NavNodeMapper.xml`

NavNodeMapper.java 新增方法：
```java
NavNode findByNodeId(@Param("nodeId") Long nodeId);
List<NavNode> findChildren(@Param("parentId") Long parentId);   // 删一级时查子节点
void insert(NavNode node);              // useGeneratedKeys 回填 nodeId
void update(NavNode node);              // 按 nodeId 全字段更新
void logicalDelete(@Param("nodeId") Long nodeId);   // SET is_deleted=1
```

NavNodeMapper.xml 新增：
- `<select id="findByNodeId">` -> `SELECT ... FROM nav_node WHERE node_id = #{nodeId}`
- `<select id="findChildren">` -> `SELECT ... FROM nav_node WHERE parent_id = #{parentId} AND is_deleted = 0`
- `<insert id="insert" useGeneratedKeys="true" keyProperty="nodeId">` -> INSERT node_name, parent_id, node_level, node_type, icon, sort_order
- `<update id="update">` -> UPDATE node_name, parent_id, node_level, icon, sort_order, update_time=NOW() WHERE node_id = #{nodeId}
- `<update id="logicalDelete">` -> UPDATE nav_node SET is_deleted=1, update_time=NOW() WHERE node_id = #{nodeId}

## 任务 2：后端 - NavNodeMapper 加设备挂载查询

**文件**：同上 NavNodeMapper.java + NavNodeMapper.xml

新增方法：
```java
List<Map<String, Object>> findUnmountedDevices();           // 可挂载设备（nav_node_id 为空）
int mountDevices(@Param("nodeId") Long nodeId, @Param("deviceIds") List<Long> deviceIds);
int unmountDevice(@Param("deviceDeployId") Long deviceDeployId);
int unmountAllByNode(@Param("nodeId") Long nodeId);         // 级联删除时用
int countDevicesByNodeId(@Param("nodeId") Long nodeId);     // 删前确认影响
```

XML 对应：
- `findUnmountedDevices`：`SELECT dd.device_deploy_id AS deviceDeployId, dd.device_deploy_name AS deviceDeployName, dt.device_type AS deviceType FROM device_deployment dd LEFT JOIN device_template dt ... WHERE dd.is_deleted=0 AND dd.nav_node_id IS NULL`
- `mountDevices`：`UPDATE device_deployment SET nav_node_id=#{nodeId} WHERE device_deploy_id IN <foreach>`
- `unmountDevice`：`UPDATE device_deployment SET nav_node_id=NULL WHERE device_deploy_id=#{deviceDeployId}`
- `unmountAllByNode`：`UPDATE device_deployment SET nav_node_id=NULL WHERE nav_node_id=#{nodeId}`
- `countDevicesByNodeId`：`SELECT COUNT(*) FROM device_deployment WHERE nav_node_id=#{nodeId} AND is_deleted=0`

## 任务 3：后端 - DashboardNavService 加 CRUD + 挂载逻辑

**文件**：`backend/src/main/java/com/n4monitor/service/DashboardNavService.java`

新增方法（@Transactional 标注写操作）：
- `createNode(NavNode node)`：校验 nodeName 非空；parentId 为空->nodeLevel=1，非空->nodeLevel=2 且校验父节点存在且是 level1；nodeType 默认 "group"；调 insert；返回带 nodeId 的新节点
- `updateNode(Long nodeId, NavNode node)`：findByNodeId 校验存在；merge 字段；调 update
- `deleteNode(Long nodeId)`：findByNodeId；若 level1 -> findChildren 拿到子节点列表，对每个二级子节点 unmountAllByNode + logicalDelete，再 logicalDelete 一级本身；若 level2 -> unmountAllByNode + logicalDelete。返回影响统计 {childCount, deviceCount}
- `getDeleteImpact(Long nodeId)`：删前预览影响范围（返回子节点数 + 设备数），供前端弹窗展示
- `getMountableDevices()`：调 findUnmountedDevices，转 DTO
- `mountDevices(Long nodeId, List<Long> deviceIds)`：校验 nodeId 是 level2；调 mountDevices
- `unmountDevice(Long deviceDeployId)`：调 unmountDevice

## 任务 4：后端 - DashboardNavController 加写端点

**文件**：`backend/src/main/java/com/n4monitor/controller/DashboardNavController.java`

新增端点（沿用 try/catch + ApiResponse.error 模式）：
- `POST /api/dashboard/nav/nodes` body NavNode -> createNode
- `PUT /api/dashboard/nav/nodes/{nodeId}` body NavNode -> updateNode
- `DELETE /api/dashboard/nav/nodes/{nodeId}` -> deleteNode（返回影响统计）

- `POST /api/dashboard/nav/nodes/{nodeId}/devices` body List<Long> -> 批量挂载
- `DELETE /api/dashboard/nav/devices/{deviceDeployId}/mount` -> 卸载单台

## 任务 6：前端 - 新建 SystemDeploymentView.vue

**文件**：`frontend/src/views/SystemDeploymentView.vue`（新建）

**布局**：左右双栏
- **左栏（树）**：el-tree 展示两级导航树（复用 getNavTree 数据），顶部工具栏有"新增一级节点"按钮。树节点带操作按钮（新增子节点/编辑/删除，hover 显示）。点击节点 -> 右栏切换详情。
- **右栏（详情/设备面板）**：
  - 显示当前选中节点信息（名称、层级、图标、排序）
  - 节点操作按钮：编辑、删除
  - 若是二级节点：显示"已挂载设备"表格（设备ID/名称/类型/操作-卸载），上方有"添加设备"按钮 -> 打开弹窗
  - 若是一级节点：显示"下属二级节点"概览列表（只读，提示点子节点管理设备）

**新增/编辑弹窗**：el-dialog + el-form，字段：节点名（必填）、父节点选择（el-select，仅新增二级或编辑时可改；新增一级时此项禁用/隐藏）、图标选择（el-select 预设下拉，选项：Location/Picture/OfficeBuilding/Fan/Grid/Lightning/Warning/EditPen，带图标预览）、排序序号（el-input-number）。

**添加设备弹窗**：el-dialog + el-table（带 selection 多选），列出可挂载设备（getMountableDevices），确认后调 mountDevices 批量挂载，刷新已挂载列表。

**删除确认**：先调 getDeleteImpact 拿到影响范围，ElMessageBox.confirm 显示"将删除 N 个子节点、解绑 M 台设备"，确认后调 deleteNode。

样式沿用全局深色主题（el-table 暗色已在 global.scss 覆盖）。
